# Actionable EEG-ADK Multi-Agent System

This project is a sophisticated, multi-agent AI framework designed to automate the processing, filtering, and reporting of EEG data. By leveraging a state-graph architecture (LangGraph) and a memory-safe Stateful Jupyter Docker Sandbox, it mitigates the instability and reproducibility crisis often found in conventional EEG workflows.

## 🧠 Architecture Overview

The system operates via three specialized AI agents interacting through a shared state:

1. **Planner (Strategist):** Translates your natural language directives into a concrete MNE-Python pipeline. It uses a **Metadata Extractor** tool to read your EEG file headers without loading massive datasets into memory, and a **Scientific RAG** tool to autonomously fill in missing parameters (like standard bandpass frequencies for specific paradigms).
2. **Executor (Programmer):** Writes memory-safe Python code based on the Planner's blueprint and executes it inside a **Stateful Jupyter Sandbox**. If an error occurs (e.g., a missing channel), it recursively reads the traceback and patches the code up to 5 times.
3. **Critic (Reviewer):** A Multimodal Vision-Language Model that visually inspects the Base64 plots generated by the Executor. It ensures signal-to-noise ratio is adequate, rejects artifacts (like persistent eye-blinks), and drafts the final manuscript-ready Methods and Results section.

## 🛠 Prerequisites

- **Python 3.10+**

## 🚀 Setup & Installation

### 1. Install Dependencies
Install the required orchestration packages on your host machine:
```bash
pip install -r requirements.txt
```

### 2. Configure Environment Variables
Create a `.env` file in the root directory. 

By default, the system is configured to use a local `vLLM` server. However, you can easily switch to **Google Gemini** by changing the `LLM_PROVIDER`.

**Example `.env` (Using Gemini):**
```env
LLM_PROVIDER=gemini
GOOGLE_API_KEY=your_gemini_api_key_here
GEMINI_MODEL=gemini-1.5-pro

# Docker Sandbox Endpoints
GATEWAY_URL=http://localhost:8888
WS_GATEWAY_URL=ws://localhost:8888
JUPYTER_TOKEN=eeg_adk_sandbox_token
```

**Example `.env` (Using Local vLLM):**
```env
LLM_PROVIDER=vllm
VLLM_API_BASE=http://localhost:8000/v1
VLLM_API_KEY=EMPTY
VLLM_MODEL=mistralai/Mixtral-8x7B-Instruct-v0.1
VLM_MODEL=llava-hf/llava-1.5-7b-hf
```

### 3. Start the Docker Sandbox
The Executor agent requires the isolated Docker container to safely execute generated MNE/EEGLAB code without crashing your host machine.
```bash
cd docker
docker-compose up -d --build
```
*Note: This image includes MATLAB Runtime, EEGLAB, and MNE-Python, so the initial build may take some time.*

### 4. Prepare the Knowledge Base (RAG)
For the Planner and Executor agents to intelligently infer standard EEG parameters and use the MNE API correctly, you should populate the Vector Database:
1. Place standard methodology papers (e.g., P300/N400 processing guidelines) as **PDF** files and official MNE-Python API documentation as **Markdown/TXT** files into the newly created `rag_docs/` directory at the root of the project.
2. Run the ingestion script:
   ```bash
   python scripts/ingest_rag_data.py
   ```
This will automatically parse, chunk, and embed the documents into the local ChromaDB.

## 📊 Usage Instructions

### 1. Prepare Your Data
To maintain security and path consistency with the Docker Sandbox, **all EEG data must be placed inside the `data/` directory** located at the root of the project.
```bash
mkdir -p data
cp /path/to/your/eeg_recording.fif ./data/
```

### 2. Run the Multi-Agent Workflow
Execute the main entrypoint:
```bash
python main.py
```

### 3. The Human-In-The-Loop (HITL) Process
1. **Ingestion:** The system will prompt you for the filename of your data (relative to the `data/` directory) and your high-level directive (e.g., *"Filter 1-30Hz, apply ICA, and epoch on trigger 'Stimulus/1'"*).
2. **Review Plan:** The Planner will generate a Markdown plan. Execution will pause.
3. **Approve/Edit:** Press `ENTER` to approve the plan and pass it to the Executor, or type corrective feedback to dynamically adjust the pipeline.
4. **Execution & Final Report:** The Executor will run the code in the Docker sandbox, the Critic will review the output plots, and a final consolidated report will be saved to `output/final_report.md`.

---

## ⚠️ Known Limitations
- **Data Pathing:** Do not provide absolute paths from your host machine (e.g., `/home/user/data.set`). The Docker container cannot access them. Only provide paths relative to the `data/` directory.
- **RAG Vector Database:** The `chromadb` instance must be populated with research PDFs to fully utilize the `scientific_rag` tool. Currently, if no documents match, the agent falls back to its foundational heuristic knowledge.
